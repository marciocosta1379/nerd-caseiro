## Passo 1 — Conectar o BME280 ao ESP32

O BME280 usa protocolo I2C: apenas 4 fios. Faça a conexão:

| BME280 | ESP32 DevKit |
|--------|-------------|
| VCC | 3V3 |
| GND | GND |
| SDA | GPIO21 |
| SCL | GPIO22 |

![ESP32 DevKit NodeMCU Wi-Fi Bluetooth](/images/produtos/esp32-devkit-nodemcu.webp)

> **Atenção:** use o pino **3V3** do ESP32, não o 5V. O BME280 opera em 3,3V — tensão maior danifica o sensor.

O pino SDO do BME280 determina o endereço I2C:
- SDO conectado ao GND → endereço `0x76` (padrão da maioria dos módulos)
- SDO conectado ao VCC → endereço `0x77`

Se não tiver certeza, use `0x76` e o ESPHome mostrará um erro de comunicação se o endereço estiver errado — fácil de identificar nos logs.

## Passo 2 — Instalar o ESPHome no Home Assistant

O jeito mais simples é pelo **Add-on do Home Assistant**:

1. Vá em **Configurações → Add-ons → Add-on Store**
2. Procure por **ESPHome** e instale
3. Inicie o add-on e abra a interface Web

Se preferir instalar via pip (para usar fora do HA):

```bash
pip install esphome
```

## Passo 3 — Criar a configuração ESPHome

Na interface do ESPHome, clique em **"+ New Device"**, escolha ESP32 e dê um nome (ex.: `sensor-sala`).

Substitua o conteúdo gerado pelo YAML abaixo — este é o arquivo que uso nos meus sensores, testado e funcionando:

```yaml
esphome:
  name: sensor-sala
  friendly_name: Sensor Sala

esp32:
  board: esp32dev
  framework:
    type: arduino

# Logging local (útil para debug via USB)
logger:

# API para o Home Assistant — gere sua chave em esphome.io/docs/api
api:
  encryption:
    key: !secret api_key

# Atualização OTA — nunca mais precisa conectar o cabo USB
ota:
  - platform: esphome
    password: !secret ota_password

wifi:
  ssid: !secret wifi_ssid
  password: !secret wifi_password

  # Hotspot de fallback se o Wi-Fi falhar
  ap:
    ssid: "Sensor-Sala Fallback"
    password: "12345678"

captive_portal:

# Barramento I2C — pinos padrão do ESP32 DevKit
i2c:
  sda: GPIO21
  scl: GPIO22
  scan: true  # mostra dispositivos encontrados no boot

sensor:
  - platform: bme280_i2c
    temperature:
      name: "Temperatura"
      oversampling: 16x
      filters:
        - offset: -2.0  # ajuste de calibração: compensar calor do ESP32
    humidity:
      name: "Umidade"
      oversampling: 16x
    pressure:
      name: "Pressão Barométrica"
    address: 0x76
    update_interval: 60s
```

![Sensor BME280 Temperatura Umidade Pressão I2C](/images/produtos/sensor-bme280-i2c.webp)

**Sobre o arquivo `secrets.yaml`** (no mesmo diretório da config):

```yaml
wifi_ssid: "Nome da sua rede Wi-Fi"
wifi_password: "Senha do Wi-Fi"
api_key: "gere-em-esphome-io/api"
ota_password: "senha-ota-qualquer"
```

O `offset: -2.0` na temperatura compensa o aquecimento do próprio ESP32 que irradia para o BME280. O valor exato varia com o layout da sua montagem: meça com um termômetro de referência e ajuste.

## Passo 4 — Gravar o firmware no ESP32

Conecte o ESP32 via USB ao computador onde o ESPHome está rodando.

Na interface ESPHome, clique em **"Install"** → **"Plug into this computer"** e aguarde a compilação e gravação (primeira vez leva 3-5 minutos para compilar).

Se aparecer erro de porta serial no Windows, instale o driver [CP210x](https://www.silabs.com/developers/usb-to-uart-bridge-vcp-drivers) — comum nas primeiras gravações.

Após gravar, o ESP32 conecta ao Wi-Fi e já começa a transmitir dados. Nos logs você vai ver:

```
[I][i2c:028]: Found i2c device at address 0x76
[I][bme280:062]: Got temperature=22.3°C humidity=58.1% pressure=1013.2hPa
```

- `sensor.sensor_sala_umidade`

## Passo 6 — Automação de exemplo: alerta de umidade baixa

Esta automação envia notificação quando a umidade cai abaixo de 40% — útil no inverno com aquecedor ligado:

```yaml
automation:
  - alias: "Alerta umidade baixa — sala"
    description: "Avisa quando o ar fica seco demais"
    trigger:
      - platform: numeric_state
        entity_id: sensor.sensor_sala_umidade
        below: 40
        for:
          minutes: 10  # evita alertas de leituras momentâneas
    condition: []
    action:
      - service: notify.mobile_app_seu_celular
        data:
          title: "Umidade baixa"
          message: >
            Sala com {{ states('sensor.sensor_sala_umidade') }}% de umidade.
            Considere ligar o umidificador.
    mode: single
```

E a automação inversa para quando normaliza:

```yaml
  - alias: "Umidade sala normalizada"
    trigger:
      - platform: numeric_state
        entity_id: sensor.sensor_sala_umidade
        above: 45
    action:
      - service: notify.mobile_app_seu_celular
        data:
          message: "Umidade da sala voltou ao normal: {{ states('sensor.sensor_sala_umidade') }}%"
    mode: single
```

## Troubleshooting

**Sensor não aparece no I2C scan:** verifique se SDA/SCL não estão invertidos. Confira também se o módulo BME280 que você recebeu usa 0x76 ou 0x77 — há módulos dos dois tipos no mercado.

**Temperatura lendo 2-5°C acima do real:** normal — é o calor do ESP32. Ajuste o `offset` no YAML para corrigir. Para precisão máxima, monte o BME280 em fio de extensão (10 cm de jumper) longe do ESP32.

**Wi-Fi cai constantemente:** ative o modo de potência máxima adicionando ao YAML:
```yaml
wifi:
  power_save_mode: none
```

**Firmware não grava (porta serial não encontrada):** instale o driver CP210x ou CH340 dependendo do chip USB-serial do seu ESP32.
